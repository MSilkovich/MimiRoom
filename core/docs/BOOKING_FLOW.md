# Как устроена система бронирования (core)

> Кратко: **кто может что и когда** (user / service) → **сетка доступного времени** (slots) → **факт записи** (bookings). Слоты материализуют свободное время, брони его занимают.

## Таблицы и роли

| Таблица | Роль |
|---|---|
| `user` | аккаунты: клиенты, мастера (`role=groomer`), менеджеры |
| `service` | услуга: длительность + буферы до/после, цена |
| `master_services` | M2M: какие мастера (`user`) оказывают какие услуги |
| `work_schedules` | регулярный график мастера: день недели + начало/конец + выходной |
| `slots` | конкретный интервал под `(master, service, дата)`, статус `free/booked/blocked` |
| `bookings` | факт записи: слот + клиент (`client_id` или контакт гостя) + `pet_id` + `comment/options` |
| `pet` | питомцы клиента (`owner_id` → `user`) |

## Цепочка данных

```
user (мастер, role=groomer) ── master_services ── service
        │
  work_schedules
        │  генерация
        ▼
     slots ── booking ── pet
        ▲        │
 активные ───────┘  client (user) / contact
```

## Поток записи

1. **Настройка:** мастер (`user.role=groomer`) ↔ услуги (`master_services`), график (`work_schedules`), у услуги — `duration_minutes` + буферы.
2. **Выбор:** клиент / фронт / интеграция выбирает услугу, дату, при желании мастера.
3. **Доступность:** `GET /slots/availability?master_id&service_id&date_from&date_to` — генератор по графику и `duration + buffer_before + buffer_after` строит сетку; статусы пересчитываются по активным броням (`booked` / `blocked`), отдаются свободные.
4. **Бронь:** `POST /bookings {slot_id, client_id | client_name+client_phone, pet_id?, options?}` — в транзакции: advisory-lock по мастеру + `FOR UPDATE` слота + проверка пересечений → создаётся booking, слот `booked`, соседние по буферам `blocked`.
5. **Отмена:** booking → `cancelled`, пересчёт → слот снова `free`.

## Почему так

- `slots` материализуют доступное время: удобно показывать, бронировать, блокировать; уникальность `(master_id, service_id, start_time)` и уникальный индекс по `slot_id` ловят гонки.
- `booking` ссылается на `slot_id`, поэтому время/мастер/услуга не «расцепляются».
- Один `booking` = один слот = одна услуга. Несколько услуг/питомцев = несколько слотов/броней.
- Мастер — это `user` с `role=groomer`: календарь/график привязан к тому же аккаунту, что и права/авторизация. Отдельной таблицы `resources` нет.
- Клиент: `client_id` (авторизованный) **или** `client_name`/`client_phone` (гость/интеграция). Имя/телефон в брони — снимок контакта на момент записи.
- `options` — произвольные доп. данные (источник интеграции, пожелания); `pet_id` — питомец клиента.

## Статусы

- `slot`: `free` → `booked` (активная бронь) / `blocked` (пересечение по буферам) → `free` (отмена).
- `booking`: `pending` → `confirmed` → `cancelled`.
