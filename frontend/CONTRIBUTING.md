# Работа команды

Начните с [README](README.md) и [инструкции интеграции](docs/DEVELOPMENT.md).

1. Обновите `main`: `git switch main`, затем `git pull --ff-only`.
2. Создайте ветку: `git switch -c feature/booking-api`.
3. Внесите изменения, выполните `npm run check` и `npm test`.
4. Отправьте ветку и откройте pull request. Укажите, что изменилось, как проверить и затронут ли API.

В `main` хранится запускаемый вариант. Изменения контракта согласовывайте между фронтендом, бэкендом и ботом в одном pull request либо со ссылкой на связанный PR.

Не коммитьте `.env.local`, токены, клиентские выгрузки, `.data/`, `node_modules/` и сгенерированные автономные HTML. Общие настройки описывайте в `.env.example` с пустыми секретами. Бинарные сборки генерируются командой `npm run package`.

При изменениях записи проверяйте пересечение визитов, отмену и перенос. При изменениях авторизации — права клиента и мастера на чужие данные. Тесты в этом репозитории не заменяют серверные проверки доступа и транзакций.
