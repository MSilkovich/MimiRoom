# Следующие изменения контракта

Фронтенд использует существующие endpoints из openapi.json. Расчёт доступности и защита от пересечений принадлежат core.

Для следующего этапа полезны: атомарный перенос записи (сейчас BookingUpdate не принимает время/мастера/услугу); изменение consumables существующей услуги; endpoints задач смены и очереди поддержки; серверные платежи и уведомления. До появления контрактов такие действия не выдаются за серверные функции.

Telegram-link: frontend получает код/deep_link; tg сервис завершает привязку. Полный сквозной тест требует настроенного бота и живой базы. Эксплуатационное тестирование выполняется на окружении команды после настройки core/Redis/PostgreSQL.
