# Обновление frontend · 0.5.0

Фронтенд перенесён в `frontend/` общего репозитория. Исходная спецификация приложена без изменений в `docs/openapi.json`; версия URL остаётся v0.0.1.

## Изменения

- Клиентский кабинет и пространство команды с отдельной навигацией и адаптивным интерфейсом в стиле МиМиРум.
- Запись по серверным окошкам: питомец → услуга → мастер → свободное время → подтверждение. Выбор дат, группировка времени, пустые состояния, загрузка, повтор запроса.
- POST slots/available вместо GET; сохранение точного start_time выбранного окошка. Даты показываются по Москве, независимо от часового пояса устройства.
- /bookings вместо /book; booking_id адаптируется к интерфейсу; pending/confirmed/completed/cancelled. Отдельные действия подтверждения, завершения и отмены с сохранением истории.
- Конфликт 409 возвращает к выбору времени и обновляет доступность. Повторный клик при сохранении блокируется.
- Команда: карточки мастеров, назначение услуг, недельные графики и выходные. Услуги с длительностью, буферами, породой, мастерами и расходниками при создании.
- Профиль клиента, контакты, питомцы, история ухода из API и одноразовая ссылка привязки Telegram.
- Права admin/manager/groomer/client: разные запросы и элементы управления. Admin получает страницу управления ролями; изменение собственной роли запрещено.
- JWT refresh с объединением одновременных обновлений; постраничная загрузка списков, понятные ошибки валидации и потери соединения.
- Same-origin proxy к core, настройка через CORE_API_URL, Dockerfile, CI и инструкции для backend/bot разработчиков.
- Автотесты контракта, доступа, сценариев клиентского кабинета, прокси и браузерные проверки.

## Границы контракта

API не позволяет менять время, мастера и услугу существующей записи через BookingUpdate. Фронтенд это не имитирует: перенос требует новой записи и отдельной отмены прежней, либо расширения API. Обновление норм расхода у существующей услуги также не предусмотрено ServiceUpdate. Привязка Telegram выдаёт одноразовую ссылку; обработка кода остаётся задачей tg backend.

Демо-задачи смены и очередь ИИ-поддержки остаются локальными возможностями прежнего интерфейса; серверных endpoints для них в новой спецификации нет. Это не новые сущности core.

## Проверка интеграции

Автотесты и браузерный стенд используют контрактные ответы тестового core. Локальный запуск Chrome ограничен средой; браузерный сценарий включён в GitHub CI. Полный стек PostgreSQL/Redis/Telegram с реальными ключами и Docker требует окружения команды и отдельно здесь не проверялся.
